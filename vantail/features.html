Feature details

Preview environments for every branch

Open a pull request and Vantail builds it on its own URL. The link appears in the review, updates on every push and is cleaned up when you merge.

  • Private or public preview links
  • Separate environment variables for previews
  • Automatic clean-up after merge

Rollbacks in one command

Every build is immutable and kept. When something breaks, put the last good build back in seconds, without rebuilding anything.

  • Instant: no rebuild, no cache warm-up
  • Roll back from the CLI or the dashboard
  • Full history of who rolled back and why

Edge hosting by default

Static files and server responses are cached in 34 regions, so pages load fast wherever your visitors are. Certificates renew on their own.

  • Automatic HTTPS for every domain
  • Smart cache invalidation on deploy
  • Region pinning for data rules

CLI, dashboard or API

Use whichever fits the moment. They all do the same things.

CLI

shell
vantail deploy --prod
vantail logs --follow
vantail env add API_KEY --scope preview

API

javascript
const res = await fetch("https://api.vantail.example/v1/deploys", {
  method: "POST",
  headers: { Authorization: `Bearer ${token}` },
  body: JSON.stringify({ project: "web", ref: "main" })
});

CI

ci.yml
deploy:
  runs: on-push
  steps:
    - run: npm i -g vantail-cli
    - run: vantail deploy --prod --token $VANTAIL_TOKEN

Everything else included

  • Encrypted secrets

    Environment variables are encrypted at rest and scoped per environment.

  • Live logs

    Structured, searchable logs, streamed to your terminal as they happen.

  • Zero config

    Vantail detects your project type and picks a build for you.

  • Build cache

    Dependencies and outputs are cached between builds, so repeat builds are quick.

  • Team roles

    Owner, developer and viewer roles, with single sign-on on Team plans.

  • Scheduled jobs

    Run tasks on a schedule next to your app, with logs and retries.

  • Audit log

    Every deploy, rollback and settings change, with who did it and when.

  • Smart alerts

    Failed builds and error spikes go to the right person, in the right place.

  • Webhooks and API

    Everything in the dashboard is available through a documented API.
