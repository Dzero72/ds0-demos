Preview environments, from idea to every branch

How we rebuilt previews so every branch gets a stable URL, and what we learned about caching, cost and clean-up along the way.

Jun ParkEngineering Manager
12 November 2026 · 10 min read

When we launched previews two years ago, they only existed for pull requests. That covered most reviews, but it left a gap: people push branches long before they open a pull request, and those branches had nowhere to live.

This post walks through how we changed that, so every branch now gets its own environment, without making builds slower or bills bigger.

The problem with pull-request previews

Tying a preview to a pull request felt natural, but it caused three problems in practice:

  • Designers could not see work in progress until a pull request existed.
  • Closing and reopening a pull request created a new URL each time.
  • Links pasted into chat broke as soon as the pull request was merged.

Designing stable URLs

The fix sounds simple: derive the URL from the branch name instead of the pull request number. The details were harder, because branch names can be long, contain slashes and be reused after deletion.

Naming rules

We slugify the branch name, cut it to 40 characters and add a short hash of the full name so two similar branches never collide:

slug.js
export function previewSlug(branch) {
  const base = branch.toLowerCase().replace(/[^a-z0-9]+/g, "-").slice(0, 40);
  return `${base}-${hash(branch).slice(0, 6)}`;
}

Sharing the cache

Building every branch could have doubled our build minutes. Instead, branch builds start from the latest production cache, so most of them only rebuild the files that changed.

The cheapest build is the one that reuses the work production already did.

Cleaning up

Environments for deleted branches are kept for seven days, then removed. If someone opens an old link, they see which branch it belonged to and a link to the current production site.

Results

Six weeks after launch, 64% of previews were opened before a pull request existed, and median build time for branch previews dropped to 41 seconds. Average build minutes per team went up by only 6%.

Branch previews are available on every plan today. Read the docs to turn on private previews for your team.
